Detecting prompt injection with NLP

ThesisGraduation thesis, team of seven, 2025 · notebooks on GitHub

Prompt injection is when text sent to a language model tries to override its instructions. We treated detection as a text classification problem and compared five models: LSTM, BiLSTM, BERT, DeBERTa and MiniLM.

My part: I trained and fine-tuned the BERT and LSTM models.

The data came from several sources plus 17,000 prompts we generated and labelled ourselves. After cleaning, about 265,000 unique prompts were left. Our first models scored only 60 to 70% because the training and test prompts were written in different styles, which we confirmed by plotting their embeddings. Rebuilding the splits fixed it.

Scores on an unseen test set. All five models scored 96 to 99% in training, so they did worse on new data. Precision stayed high (98 to 99.9%) but recall was lower, around 77 to 86%, so some attacks got through.

The final system checks a prompt against a vector database of known attacks first, then passes anything unclear to MiniLM. We picked MiniLM because it takes 1 to 2 ms per prompt, against 9.5 to 11 ms for BERT. It runs in a web app that also shows the response from a live language model.

Automatic parking garage

HardwareESP32 project

A garage gate that checks for free space before it opens. It detects a car at the gate and looks for an open spot. If there is one, the gate opens. If not, it stays shut. A seven segment display at the gate shows how many spots are free, and a mobile app lets the garage manager see how many cars are inside.

Encryption with XOR and NOT

CGroup project, first year at university · GitHub

A console program that encrypts and decrypts text. You type a phrase and pick encrypt or decrypt. It can scramble the text two ways: XOR with a number key, or flipping every bit (NOT). The decrypt side reverses it.

It builds the string with dynamic memory, so there is no fixed length limit, and it checks the user's input and failed memory allocations. The repo has a flowchart, and the README lists what we would add next: a GUI, a keyword as the key, saving to a file, and encrypting whole files.

My part: I wrote the code together with one teammate.
